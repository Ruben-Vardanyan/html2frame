# Decisions

The product owner made these choices on 2026-10-07, after the prototype worked. Each one has an ID so code
comments and commits can refer to it.

| ID | Decision | Why |
|---|---|---|
| **D1** | **Local control panel.** Double-click `start.bat` (or `npm start`) and a page opens on `http://localhost:5600`. *(Since D21 the launchers are "Start (Windows)" and "Start (macOS)"; `npm start` runs the server without opening a page.)* There you pick the project, screens, variants and pages, and click Capture. | Easiest for everyday use; no commands to remember. A CLI entry (`node src/capture.js <settings.json>`) stays available for automation. |
| **D2** | **Pages are auto-found, then edited.** The tool crawls same-origin links from the start page (and again after each test-account login). The user unticks, renames, groups or adds pages, and the list is saved in the project's settings file. | No typing every path, but the list stays under the user's control. |
| **D3** | **Main target: static HTML folders** (plain HTML/CSS/JS, like the prototype's site). The tool serves the folder itself. A URL source (`http://localhost:3000`) is also supported for sites that need their own server. | Matches the user's projects. Serving the folder ourselves avoids clean-URL rewrites that drop `?query` (see RESEARCH). |
| **D4** | **One Figma page per screen size** (for example "Desktop", "Phone portrait"; the variant name is appended when there are several). Each page has one row per group (Public / Customer / Admin…), with a label above each row. | Keeps each screen size readable; rows match how the prototype was reviewed. |
| **D5** | **Test accounts per project.** Each account has a name and login steps (login page, fields, submit). The tool logs in once per account per browser context and also crawls that account's pages. | Many pages exist only after login (dashboard, admin). |
| **D6** | **Variants.** Named sets of `localStorage` / cookie / URL-parameter values, for example language = en, or theme = dark. Every page is captured once per variant, and the name is added to the frame, e.g. "Home — English". | Multilingual and themed sites without editing code. |
| **D7** | **Plugin hand-off: from the panel or from a file.** "Load latest from panel" (the button is now labelled **Latest from panel**) fetches `http://localhost:5600/api/captures/latest` (allowed via `devAllowedDomains`). You can also pick a saved `.json` file. | One click when the panel runs; still works offline and for shared files. |
| **D8** | **Optional steps per page** (click, type, select, wait, run JS) to capture extra states, e.g. "Payment — errors" or "Menu open". | Interactive states are part of a design. |
| **D9** | **Screens:** desktop-hd 1920×1080, desktop 1440×900, laptop 1280×800, laptop-sm 1366×768, tablet-lg 1024×1366, tablet 768×1024, phone 390×844, phone-sm 360×780, plus custom `{name, width, height}`. Orientation is **portrait / landscape / both**; desktops and laptops are landscape only. Phones and tablets are emulated as touch devices (`isMobile`, `hasTouch`). | Requested by the user; matches common device classes. |
| **D10** | **The Figma plugin stays a local development plugin** (desktop app, "Import plugin from manifest"). | Works on the free plan; nothing to publish or review. |
| **D11** | **Separate GitHub repo**, published by the user. Claude never runs `git commit`. | The user owns history and publishing. |
| **D12** | **Name: `html2frame`** (repo `Ruben-Vardanyan/html2frame`; Figma plugin name "html2frame"). | Short and neutral. It avoids "Figma" in the product name (brand guidelines) and is distinct from html.to.design. |
| **D14** | **Layout is the user's choice in the plugin** (added 2026-10-07, refines D4). *One page* (default): every screen/variant goes on the current Figma page as its own **Figma Section** (named e.g. "Desktop — English"), stacked top to bottom, each holding its group labels and frames. Figma versions without Sections get a large title instead. *Page per screen*: D4 as before. The plugin remembers the last choice (`figma.clientStorage`). | The owner prefers everything on one page; some files want separate pages. One page also avoids the free plan's limit on pages per file. |
| **D15** | **Variant dimensions** (added 2026-10-07, extends D6). A project may define `dimensions`, e.g. Language (English, Armenian) and Theme (Light, Dark), instead of a flat `variants` list. Capture makes every combination ("Armenian · Dark"); the plugin shows one checkbox list per dimension, so the user picks languages and themes independently. | A flat list hid "light" inside each language and could not express every combination. |
| **D16** | **Armenian fallback font: Calibri** (added 2026-10-07). When the page's own Armenian font is not installed in Figma, Armenian letters use Calibri; other Armenian-capable fonts (Noto Sans Armenian, Sylfaen, Segoe UI…) only when Calibri is missing too. Latin letters in the same layer keep the page's ordinary font. | The owner's choice; Figma has no per-glyph fallback, so without this the Armenian text was invisible. |
| **D17** | **Optional Auto Layout** (added 2026-10-07). A "Use Auto Layout" checkbox in the plugin (off by default, remembered) turns CSS flex rows and columns into Figma Auto Layout, only where it reproduces the captured positions; everything else keeps absolute positions. | Editable layouts like html.to.design's option, without moving anything that Auto Layout cannot express. |
| **D18** | **Publish the plugin to the Figma Community, free and open source** (added 2026-10-07; replaces D10 once done). After step 5 (panel) and step 6 (guide), the plugin is prepared for publishing: manifest with `allowedDomains: ["http://localhost:5600"]` plus a `reasoning` (so "Latest from panel" keeps working), icon, cover, listing text, data-security answers, and a link to the public open-source (GPL, D23) GitHub repo for the capture tool. The owner submits it from the Figma desktop app (two-factor authentication required; Figma reviews it). Until then D10 applies. | Free plugins can be published on any plan; people need the capture tool and a guide first, so the listing waits for steps 5–6. |
| **D19** | **Sections by screen or by group** (added 2026-10-22, refines D14). A "Sections" choice in the plugin, remembered like the layout: *Screen* (default, as D14: a Section per screen/variant with a row per group), *Group* (a Section per group, plus the variant when there are several, with a labelled row per screen) or *Group + screen* (a Section per group and screen, e.g. "My pages — Desktop", one row). With *Page per screen*, *Group* puts a Section per group on each screen's page (*Group + screen* would be the same, so it is not offered). The groups are the pages' Group column in the panel, which gets autocomplete and a "Set group" for the pages shown by the search. *(D20 replaced the Group column and "Set group" with group headers and dragging.)* | The owner wants features (e.g. "My pages") side by side for desktop and phone, or apart per screen, without a new field: groups already say which pages belong together, and the capture file does not change. |
| **D13** | **MIT License** (`LICENSE`, © 2026 Ruben Vardanyan). *(Replaced by D23 on 2026-11-12: GNU GPL v3 or later.)* It was added locally, not on GitHub, so the first push has no unrelated-history conflict. | Permissive and common for small tools. |
| **D20** | **An easier panel, built next to the current one for testing** (added 2026-11-11). `panel/next.html` (`next.js`, `next.css`), at http://localhost:5600/next.html, is the new panel; the current panel (`index.html`, `panel.js`) stays as it is and stays the one the launchers open, until the owner has tested the new one and says to replace it. Both edit the same projects through the same API and write the same settings file. What the new one changes: pages are listed in groups like a task list (fold, coloured name label, "+ New group", "+ Add a page" per group), a page is reordered or moved to another group by dragging it (the order of `pages`, and so of the frames in Figma, follows) (the old "Set group for all N" ignored the ticks; a bar moving the ticked pages was tried and dropped by the owner in favour of dragging); steps are rows (an action and what it acts on) with JSON kept as a fallback for steps the rows cannot show; a page is added inside its group, in a row with name and address; a state of a page is a short form with steps; Languages and themes, Test accounts and Local storage (was "Stored values") are sections that stay closed until used, the first two with simpler forms. The capture follows the list: group by group in the order the groups first appear, then list order inside a group (`src/capture.js`, so also for the current panel and the command line); the new panel lets groups be dragged into another order and adds a group with "+ New group" at the end of the list, where it appears. A simple/advanced switch for the whole panel was considered and rejected by the owner. **The owner approved the new panel, and on 2026-11-11 it replaced the old one** as `panel/index.html`, `panel.js` and `panel.css` (`next.*` removed; the old panel is in git history). | The panel had become heavy: most projects use only site, screens, pages and Capture, and writing steps as JSON was the hardest part. Side by side, the owner can compare and nothing that works is at risk. |
| **D21** | **An easier start, settings and updates** (added 2026-11-12). Users get html2frame with GitHub's Download ZIP (or git clone), as before; no installer, no `.exe`. The launchers are named **`Start (Windows).bat`** and **`Start (macOS).command`** (extensions are often hidden). They run `src/start.js`: the first start checks the computer (Windows 10+ or macOS 12+, **Node.js 20+**, the minimum of `playwright-core` 1.63, Edge or Chrome by a real launch, a writable folder, port 5600 free or already html2frame) and installs `playwright-core`; it saves the result in the git-ignored `.html2frame/check.json`, so later starts skip the check until something changes (Node.js version or path, html2frame version, `node_modules`). When something important is missing it **only shows a message** with the required version and waits for a key: nothing is downloaded or opened for the user. It then asks **separately** for a Desktop icon and a Start menu entry (macOS: Applications, and a Desktop link to that app); each answer is kept and can be changed in Settings. html2frame then **runs in the Start file's window** (the icons open the Start file too): the window says it runs and how to stop it; closing it stops html2frame. (A start without a window was built first and dropped by the owner: with no window, nothing showed that html2frame was running or how to stop it.) **No auto-stop:** html2frame runs until the user presses **Quit** (panel top bar, Settings) or closes the window, so "Latest from panel" keeps working after the tab is closed. Quit cancels a running capture, lets its browser close, ends the server (and with it the window), and tells every open panel tab (BroadcastChannel), which shows "html2frame has stopped" and closes itself where the browser allows it (a tab that has shown only one page). A **Settings** page: version and updates, the setup check with "Check again", the icons, the plugin's manifest path, Quit. **Updates:** checked once a week while html2frame runs, from **GitHub Releases** (the latest published release: its tag `vX.Y.Z` is the version, its notes are shown as "What's new"; drafts, pre-releases and work merged to `main` in between never reach users; versions follow Semantic Versioning, and this branch is **0.2.0**). ZIP installs: "Update now" downloads that release's ZIP, checks it holds that version, extracts it with the system's own tool (Windows `tar`, macOS `ditto`), backs up the program files, copies the new ones in, removes files the new version dropped, runs `npm install` if the dependencies changed, restarts, and puts the old version back on any error; `projects/`, `captures/`, `.html2frame/`, `node_modules/`, `.git/` are never touched. Git installs: `git fetch --tags`, then `git merge --ff-only <tag>`, only on `main` with no changed tracked files and no local commits the release lacks; otherwise Settings shows why and the command. (A first version compared `main`'s `package.json` and downloaded `main`; the owner switched to releases so that only published versions reach users.) | The owner's team and clients are not technical: git, a terminal window to keep open and a manual stop were the hard part. A downloaded unsigned `.exe` or `.app` meets SmartScreen / Gatekeeper warnings and antivirus false alarms, needs a build step and four builds, and code signing costs money; renamed launchers, a saved check, locally made icons (no quarantine flag) and a one-click update give the same ease for free. An auto-stop was rejected: a panel left open while away must still work. |
| **D22** | **Problems are reported on GitHub Issues only** (added 2026-11-12). The panel's **About** page (footer) has "Report a problem on GitHub" and "Suggest an idea": GitHub issue forms (`.github/ISSUE_TEMPLATE/bug_report.yml`, `idea.yml`) opened with "Your setup" filled in from the page (html2frame, system, Node.js and browser versions; never folder paths, projects or passwords), plus "See reported problems". No e-mail address. | One public place: reports are tracked, and people see what was already reported. The filled-in setup saves asking for versions. No address to publish or inbox to watch. |
| **D23** | **GNU GPL v3 or later, with an author credit** (added 2026-11-12; replaces D13). `LICENSE` is the GPL-3.0 text, word for word (from gnu.org); `NOTICE` holds the copyright, the "or later" grant, and an additional term under section 7(b): anyone who conveys html2frame or a work based on it, changed or not, free or paid, must keep "html2frame by Ruben Vardanyan - https://github.com/Ruben-Vardanyan/html2frame" in `NOTICE` and visible in the user interface's legal notices (the panel's About page, the plugin window's footer; a modified version says it was modified). Source files start with `// html2frame — © 2026 Ruben Vardanyan, GNU GPL v3 or later (see LICENSE and NOTICE)`; `package.json` says `GPL-3.0-or-later`. The panel footers say "GPL-3.0 License"; `/license` and `/notice` serve the two files. | The owner wants to be named as the source by anyone who changes or sells html2frame. MIT keeps the credit only inside the files and lets changed copies be closed; GPL keeps every passed-on version open source with its source code, and section 7(b) lets the author require a visible credit. Selling stays allowed (open source), so the free Figma Community release (D18) still fits. |
